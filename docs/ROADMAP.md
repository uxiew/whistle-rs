### O1 — 建立失败会话与生命周期 ✓（2026-09-29）

- [x] 覆盖 DNS、连接拒绝/超时、源站 TLS、客户端取消、规则 abort、插件失败；区分传输错误、代理生成的 502 与源站真的返回 502。
- [x] 每个请求只完成一次会话，记录阶段和诊断标识；在 UI/API/持久化中保持一致，不把异常请求吞进只有日志可见的路径。

**验收：** 使用本地可控夹具重现上述失败，检查会话出现、阶段准确、没有重复/敏感信息泄露；HTTP、MITM、SOCKS、Composer/Replay 都有明确适用范围。依赖 **Q2、S1**。

**完成记录：** 失败的请求各有一条会话，带 `error: {phase, message}`；本代理生成的 502 带 `x-whistle-rs-error`（阶段）和 `x-whistle-rs-session`（会话号），源站自己的 502 没有这两个头。会话在 body 结束时才算完成，这时才写盘、才通知嵌入 API，中途断开会补记 `response` 或 `client`。客户端拒绝证书、不解密转发的隧道也各记一条 CONNECT。控制台显示失败阶段和原因。23 个本地夹具测试逐个复现，另有一条端到端测试核对 502、接口、回调、磁盘、重启后六处一致。顺带修了错误信息泄露代理密码、嵌入 API 开了持久化却不写盘、认证插件坏了时 502 缺诊断头三个问题。插件钩子失败时放行请求、会话不标失败，留给 R1。详见 [STATUS 的 O1 记录](STATUS.md#2026-09-29-o1-失败会话与生命周期)，接口和范围见 [API](API.md#失败的请求)。

### R1 — 改写、流与降级的可见性 ✓（2026-09-29）

- [x] 审查 `--body-preview-limit` 与 `--body-rewrite-limit` 的独立边界，验证超限、压缩膨胀、SSE、chunked、取消和背压。——背压没有单独的测试，见 STATUS。
- [x] 对没有应用的算子、缓冲超限回退、`cipher` 无可用套件等给出结构化原因；决定哪些情形可降级、哪些必须拒绝，不只依靠 debug 日志。

**验收：** 阈值前/后均有测试；流式场景测首字节、字节完整性与资源释放；UI/API 能区分“命中规则”和“效果实际应用”。不能把调试用 cipher pin 当成安全策略保证。依赖 **O1、Q2**。

**完成记录：** 会话多了 `unapplied`：命中了但没执行的算子，按原因分类（超改写上限、请求超上限、事件流、压缩解不开/不支持/解开后超限、插件钩子失败、cipher 用不了），列出算子和原因；控制台 Rules 标签页划掉并标 "not applied"。这些情形全部是降级，只有认证插件失败会拦截请求。途中修掉三个比"看不见"更严重的问题：`cipher://` 只给 TLS 1.3 套件、又限 1.2 时请求任务会 panic；解压不设上限，小 gzip 能在内存里膨胀成几 GB；解不开的压缩 body 上照跑算子，会写坏响应。插件钩子加了 30 秒超时（以前没有，插件不回答时请求会一直挂着）。详见 [STATUS 的 R1 记录](STATUS.md#2026-09-29-r1-改写流与降级的可见性)。
