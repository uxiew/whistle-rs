除已勾选并注明证据的项外，本文件中的任务均为**待实施**。`[ ]` 不能因写了说明就勾选。

## P1：把“能工作”变成“可解释、可迁移”

### O1 — 建立失败会话与生命周期

- [ ] 覆盖 DNS、连接拒绝/超时、源站 TLS、客户端取消、规则 abort、插件失败；区分传输错误、代理生成的 502 与源站真的返回 502。
- [ ] 每个请求只完成一次会话，记录阶段和诊断标识；在 UI/API/持久化中保持一致，不把异常请求吞进只有日志可见的路径。

**验收：** 使用本地可控夹具重现上述失败，检查会话出现、阶段准确、没有重复/敏感信息泄露；HTTP、MITM、SOCKS、Composer/Replay 都有明确适用范围。依赖 **Q2、S1**。

### O2 — 检索、采集和自有 API 契约

- [ ] 先补 `h:`/`b:` 的按需查询和 `fc:` 的来源字段；`app:` 若无平台归因能力则继续明确“不支持”，不伪造。
- [ ] 把 UI 显示筛选与服务端采集策略分开；为截断体、二进制、会话分页/游标、错误结果写清契约。API 示例从本项目路由表生成或验证，不照搬上游 `/cgi-bin/*`。

**验收：** 检索不会因字段未加载而悄悄漏掉已知匹配；未实现条件显式报出；“不采集”的承诺能用 API 和磁盘检查验证；导出/重放对不完整数据明确提示。依赖 **O1**。

### R1 — 改写、流与降级的可见性

- [ ] 审查 `--body-preview-limit` 与 `--body-rewrite-limit` 的独立边界，验证超限、压缩膨胀、SSE、chunked、取消和背压。
- [ ] 对没有应用的算子、缓冲超限回退、`cipher` 无可用套件等给出结构化原因；决定哪些情形可降级、哪些必须拒绝，不只依靠 debug 日志。

**验收：** 阈值前/后均有测试；流式场景测首字节、字节完整性与资源释放；UI/API 能区分“命中规则”和“效果实际应用”。不能把调试用 cipher pin 当成安全策略保证。依赖 **O1、Q2**。
