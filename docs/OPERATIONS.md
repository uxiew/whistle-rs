# 安全运行与数据边界

[快速开始](../README.md) · [参数](CLI.md) · [证书](CERTIFICATES.md) · [当前已知问题](STATUS.md)

这是开发调试代理，不是已经通过隔离验收的多租户网关。只代理获授权的设备与流量；能修改规则或插件的人通常也能改变代理可访问的目的地和文件，不能把它们当作不受信任的普通配置。

## 本机使用

```sh
./target/release/whistle-rs -p 8899 --no-persist -r rules.txt   # 默认只监听 127.0.0.1
```

此命令不修改系统代理、不安装信任证书。手动把客户端 HTTP/HTTPS 代理指向 `127.0.0.1:8899`；命令行验证时注意已有 `NO_PROXY`/其他代理变量，`curl --noproxy '' -x ...` 可显式使用本代理。HTTPS 的按命令 CA 信任示例见 README。

需要只转发而不解密 HTTPS 时使用 `--no-intercept-https`。不要把它与 `-M pureProxy` 混同：本项目的 `pureProxy` 用于控制特殊控制台域名的处理，不是这项开关的可靠替代。

## 默认值与共享访问

| 项目 | 默认值 / 边界 |
| --- | --- |
| 监听 | **`127.0.0.1`**：代理端口、`-P` 控制台端口、SOCKS 端口都只有本机能连。给手机或别的机器用须显式 `-H 0.0.0.0`（或具体地址）。上游 whistle 默认监听所有网卡，这是有意偏离 |
| 控制台登录 | 未设 `-n/-w` 时不要求登录；`-N/-W` 是只读账户（只能 `GET`），**必须和 `-n/-w` 一起用**，单独给会拒绝启动——否则看着像有保护，实际谁都能改。登录只保护控制台，不是代理转发的认证 |
| 独立控制台端口 | `-P` 多开一个只服务控制台的端口；控制台在代理端口上照样可用，同一套登录，不是访问控制 |
| HTTPS | 默认拦截；源站证书默认校验。`--insecure-upstream` 降低安全性，不作为通用排障建议 |
| 历史 | 默认会话落盘，保留 7 天（启动时就清理超期文件）；`--no-persist` 只关会话落盘，仍会写 CA、规则、Values 和 `reqWrite/resWrite` 显式写的文件 |
| 跨域 | `--allow-origin` 名单上的站点既能读控制台的回答，也能**改**规则；不要为图方便开 `'*'` |

启动日志会说明谁能连：只听本机时提示怎么开放；监听非回环地址却没设控制台口令时打印 **WARN**。

**日志里有什么：** 默认只有启动、警告、失败的请求（`#编号 方法 URL -> failed at 阶段: 原因`）和认证插件拦下的请求，这几行里的 URL 截到 `?` 或 `#` 之前，查询参数里常有令牌。成功的请求默认一行都不打，和上游一样；加 `-v` 时每个请求一行，URL 是完整的，查询参数也在，别把这样的日志交给不该看到令牌的人或系统。控制台里的会话始终是完整 URL。以前（2026-10-06 之前）默认就为每个请求打一行完整 URL。

**给局域网用时，本项目不提供代理本身的访问控制**：没有代理认证、没有 IP 白名单。能连上代理端口的设备都能用它转发，也都能打开控制台（有口令则需登录）。必须靠操作系统防火墙、受控网络或安全隧道限制谁能连；不要在路由器上把代理端口映射到公网。口令用环境变量 `WHISTLE_RS_PASSWORD`、`WHISTLE_RS_GUEST_PASSWORD` 给，别用 `-w`/`-W`：命令行在进程列表里，本机任何用户都能看到（见 [CLI](CLI.md#listening-beyond-this-machine)）。不要把真实密码写进仓库、报告或演示命令。

`multiEnv`/`enableRequestHeaderRules` 允许请求携带规则，而规则能读写本机文件，所以只在已限定调用者的场景启用。它不是租户隔离机制。插件和远程规则来源须受信任。

### 控制台的保护

- **跨站写入被拒绝。** 浏览器发出的 POST/DELETE 带着 `Origin`，只有控制台自己的页面或 `--allow-origin` 名单上的站点才能改东西，别的网页会得到 `403 cross-site request refused`。不带 `Origin` 的请求（curl、脚本）不受影响。以前任何网页都能用一个 `text/plain` 的 POST 改掉规则。
- **只认控制台自己的名字。** 控制台只在 Host 是 IP、`localhost` 或控制台主机名（内置的和 `-l` 加的）时应答，挡住 DNS rebinding。在代理端口上，别的 Host 会被当成普通请求转发给那个域名（和上游一样，没配代理的客户端靠这个也能用规则）；如果这个域名解析回本机，得到的是跳到 `http://<IP>:<端口>/…` 的 `302`，拿不到控制台数据。`-P` 单独开的控制台端口不转发，直接 `403`。想用别的域名打开控制台，用 `-l 那个域名`。
- **请求体上限 16 MiB**，超过回 `413`。
- **插件页面收不到控制台的登录凭据**（`Authorization`/`Proxy-Authorization` 在交给插件前去掉）。
- **客户端给本代理的 `Proxy-Authorization` 不会发给源站**，只在经上游代理转发时交给上游代理；规则主动设置的照常发送。上游 whistle 会原样转发给源站，这是有意偏离。

这些检查都不能替代登录：局域网里的设备可以直接用 curl 调 API。能改规则的人能让代理读写本机任意文件（`file://`、`resWrite://`），所以控制台的写权限等同于这个账户的文件权限。

## 采集与保留

Body 预览默认 16 KiB；缓冲响应改写上限默认 16 MiB。两者不是同一设置，也不是整个进程的内存上限。预览、导出和重放涉及有界捕获数据，不能假设每个报文都完整；达到改写上限时部分操作可能回退为原样转发，见 RULES 与 STATUS。

控制台搜索、Include/Exclude 显示筛选与服务端“是否采集”是不同层。**画面没显示不证明内存/API/磁盘没有该请求。** 真正不进记录的只有规则 `enable://hide`；`--no-persist` 只是不写盘。哪种做法挡住了哪里，见 [API 的「采集和显示是两回事」](API.md#采集和显示是两回事)。会话可能含 Authorization、Cookie、个人数据或业务密钥；分享 HAR、JSONL、截图及插件日志前审查内容。

默认存储在 `~/.whistle-rs`，也可用 `--dir` 指定专用目录。在 Unix 上，私钥、会话、规则和 Values 文件以 `0600` 创建，本项目自己的子目录（`certs/`、`rules/`、`sessions/`）为 `0700`；旧版本留下的 `0644` 私钥在下次启动时收紧。`--dir` 指到一个已存在的目录时，不会改那个目录本身的权限。CA 证书可以交给获授权的客户端，私钥不能分享。

几种"删掉"是不同的操作：

| 操作 | 影响 |
| --- | --- |
| 控制台里的筛选 / 搜索 | 只影响显示，内存、API、磁盘都还有 |
| **Clear**（`POST /api/sessions/clear`） | 只清内存；已落盘的历史还在，**重启后会回来** |
| **Delete history**（`POST /api/sessions/purge`） | 清内存并删除全部会话文件，重启后也没有 |
| 保留期（`--persist-days`，默认 7） | 启动时和跨天时删除超期文件 |
| 大小上限（`--persist-max-mb`，默认 1024） | 和保留期哪个先到按哪个。启动时、写入使它超过时，按天删整个文件，从最老的删起；只剩当天的文件还超，就把它截到上限的一半，只留最新的整行。每删一次写一条 INFO 日志。一条会话连同 body 预览写下来最多约 21 KB，1 GiB 大约 5 万条 |
| 启动时读回 | 从最新的文件末尾往前，读够 `-R` 条（默认 600）就停，历史再大也不多占内存：1 GB 历史启动时 18 MiB、0.1 秒（以前整份读进来，886 MiB、2.5 秒） |
| `--no-persist` | 不写、不读会话文件；不删除以前留下的 |
| 写盘时机 | 一条会话**完成时**写一次：body 传完、失败或客户端离开。一直不结束的流在结束前不写。Ctrl+C 或 `kill` 停下时，先把已完成的会话写完再退出；还开着的流不进历史，`kill -9` 时刚完成、还没来得及写的最后几条也可能丢 |

HAR 导出和 `/api/export` 的内容原样包含请求头（含 `Authorization`、`Cookie`）和 Values，分享前先审查。删除/迁移目录前先停止对应实例，避免误删其他实例的数据。

## 排障顺序

先确认客户端真的经过本代理，再用 `explain` / Test Rules 查匹配，最后查看请求详情和日志。失败的请求（DNS、连接、TLS、源站中途断开、客户端先走了）也各有一条会话，行上的红色标签写着停在哪一步，详情第一张卡片写着原因；客户端收到的 502 带 `x-whistle-rs-session`，是那条会话的编号，日志里对应那行也以 `#编号` 开头。阶段含义见 [Cookbook](COOKBOOK.zh-CN.md#规则不生效时)。

写延迟用纯数字毫秒，例如 `resDelay://1000`；`1s`、`500ms` 不是有效的延迟数值。证书错误优先核查信任关系、源站证书和目标端口，不用关闭所有校验掩盖问题。停止调试后撤销不再需要的客户端代理设置与 CA 信任。
